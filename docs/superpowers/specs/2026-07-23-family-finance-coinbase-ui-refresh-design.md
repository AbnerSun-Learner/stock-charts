# 家庭财务页面 Coinbase 主题优化设计

> 日期：2026-07-23  
> 状态：已获用户方案确认，待实施  
> 主题参考：[VoltAgent/awesome-design-md · Coinbase](https://github.com/VoltAgent/awesome-design-md/tree/main/design-md/coinbase)

## 1. 目标

在不改变家庭财务业务逻辑的前提下，统一优化以下页面的 UI/UX：

- `/view/family`：家庭财务总览
- `/view/family/ledger`：家庭资产记账

采用 Coinbase 设计语言中的白色 / 浅灰平面、单一蓝色强调、24px 大卡片圆角、胶囊主按钮、克制阴影和清晰的金融信息层级。首页家庭资产入口卡片的现有优化保留。

## 2. 范围与非目标

### 2.1 本次修改

- 家庭总览和资产记账页的页面头、内容层级、卡片外观、间距及响应式布局
- 总览页的三项 KPI、资产结构、心理账户和家庭保单区块
- 记账页的资产结构、条目管理和成员资产变动区块
- 两个页面共用的局部主题 token 与可复用展示组件
- 总览无资产条目时的空状态布局

### 2.2 明确不修改

- Supabase 查询、Repository、聚合计算和历史快照逻辑
- 登录鉴权、成员 Drawer、条目和保单 CRUD
- 桑基图、饼图、折线图的数据结构与业务含义
- `/view/family/policies` 独立页面
- 首页其他投研卡片
- `package.json`、依赖或全局 Ant Design 主题

## 3. 视觉原则

### 3.1 色彩与表面

- 页面主表面使用白色和浅灰色，避免背景渐变和多层装饰性阴影。
- 蓝色只用于主操作、家庭资产识别和必要的强调信息。
- 总负债使用中性灰；净资产仅在正负值上使用克制的绿 / 红语义色。
- 所有主题变量必须限定在家庭财务页面根作用域，不能影响其他业务页面。

固定 token：

| 角色 | 值 |
| --- | --- |
| Primary | `#0052ff` |
| Primary active | `#003ecc` |
| Ink | `#0a0b0d` |
| Body | `#5b616e` |
| Muted | `#7c828a` |
| Hairline | `#dee1e6` |
| Surface soft | `#f7f7f7` |
| Surface strong | `#eef0f3` |
| Positive | `#05b169` |
| Negative | `#cf202f` |
| Card radius | `24px` |
| Compact radius | `12px` |
| Pill radius | `999px` |
| Single shadow | `0 4px 12px rgba(10, 11, 13, 0.04)` |

### 3.2 形状与间距

- 主要内容卡片固定使用 24px 圆角和 1px hairline 边框；紧凑的内层容器固定使用 12px 圆角。
- 主按钮使用 44px 以上高度和胶囊圆角；次级按钮使用浅灰或描边样式。
- 页面模块间保持 24px，卡片内部保持 20–32px，形成稳定的阅读节奏。
- 只保留一个轻阴影层级，不为嵌套卡片叠加深阴影。

### 3.3 字体与数字

- 页面标题使用正常字重和紧凑字距，避免交易平台式粗重标题。
- 金额使用系统等宽字体栈，保证不同位数对齐并提高扫读效率。
- 标题层级严格按 `h1 → h2 → h3` 组织。

## 4. `/view/family` 总览设计

### 4.1 页面头

- 增加家庭财务专属根作用域。
- 页头包含“家庭财务总览”、说明文字、成员管理次级按钮和更新资产主按钮。
- 桌面端标题与操作左右排列；移动端纵向排列，操作按钮保持足够点击面积。

### 4.2 KPI 摘要

- 保留总资产、总负债、净资产三项实时活账汇总。
- 三项指标使用统一卡片结构和数字排版，不改变 `computeLedgerTotals` 或 `formatCny`。
- 总资产使用蓝色识别；总负债使用中性灰；净资产根据正负值使用语义色。
- loading 状态继续由 Ant Design Card / Statistic 处理。

### 4.3 资产结构

- 桑基图作为页面主要分析区块，增加简短说明和更充分的内容留白。
- 不修改 `FamilyAssetSankey` 的数据和图表配置。

### 4.4 心理账户与家庭保单

- 继续使用桌面双栏、移动单栏布局。
- 统一外层卡片边框、圆角、标题层级、操作按钮和空状态。
- `FamilyMentalAccountsPanel` 与 `FamilyPoliciesPage` 的内部 CRUD 和加载行为不变。

### 4.5 无资产空状态

- 空状态使用同一页面头，并在独立引导卡中说明先完成资产记账。
- 主操作仍跳转 `/view/family/ledger`；家庭保单区块继续可用。

## 5. `/view/family/ledger` 记账页设计

### 5.1 页面头

- 页头包含“家庭资产记账”、用途说明和“添加资产/负债”主按钮。
- **删除当前标题下的“总资产 / 总负债 / 净资产”汇总文本。**
- **Ledger 不新增 KPI 摘要卡；资产 KPI 只在总览页展示。**

### 5.2 主工作区

- 左侧为资产结构分析卡，保留 `FamilyAssetStructurePie` 和原空状态。
- 右侧为条目管理卡，资产表和负债表继续同时展示，不改为 Tabs。
- 添加操作从条目卡内部提升到页面头，减少重复操作入口。
- 编辑和删除仍保留为显式操作列。

### 5.3 成员资产变动

- 作为独立分析区块，保留每位成员一张折线图的现有规则。
- 统一成员图表卡片的边框、圆角、标题和间距。
- 不增加家庭总资产折线图，不修改每日快照逻辑。

### 5.4 Modal

- 添加 / 编辑条目 Modal 的字段、校验、同步保存锁和错误处理保持不变。
- 仅允许在家庭页面作用域内调整按钮、输入框圆角等视觉细节。

## 6. 组件与样式边界

- 可新增复用的 KPI 展示组件，供总览三项指标使用；Ledger 不消费该组件。
- 页面组件分别使用 `family-overview-page`、`family-ledger-page` 等唯一根 class。
- 公共家庭主题 class 必须以 `family-finance-` 开头。
- 不使用未限定作用域的 `.ant-card`、`.ant-table` 或 `.ant-btn` 选择器。
- 子组件需要视觉容器时，通过显式 `className` 或页面外层包装传递，不改业务 props。

## 7. 数据流与错误处理

- 页面加载、并行请求和 `reload` 调用顺序保持不变。
- 原有 `try/catch/finally`、message 提示、Modal 保存锁和失败保留行为保持不变。
- UI 改造不能新增请求、缓存或衍生业务状态。

## 8. 响应式与可访问性

- `>= 1024px`：总览下半区双栏；Ledger 主工作区双栏。
- `< 1024px`：分析和操作区折叠为单列。
- `< 640px`：页头操作纵向排列，主 CTA 可满宽；内容卡片缩小内边距。
- 表格在窄屏下允许横向滚动，不压缩金额和操作列到不可读。
- CTA 高度不少于 44px，装饰图形使用 `aria-hidden`，页面标题保持正确层级。
- 正文和金额必须满足明亮背景下的可读对比度。

## 9. 验收标准

- 首页家庭资产入口卡片改动保留，其他首页卡片无 diff。
- `/view/family` 完成页头、KPI、资产结构、心理账户、保单和空状态的统一优化。
- `/view/family/ledger` 完成页头、资产结构、条目管理和历史区块优化。
- Ledger 页不再显示总资产 / 总负债 / 净资产汇总文本或 KPI 卡片。
- 除明确从条目卡迁移至页头的“添加资产/负债”入口外，其他原有按钮、跳转、Drawer、Modal 和 CRUD 流程保持可用。
- `/view/family/policies` 独立页无视觉与行为回归，嵌入总览的保单组件样式不得外溢。
- 家庭财务相关单测、ESLint、生产构建通过。
- 独立 code reviewer 确认样式作用域和功能边界无回归。
