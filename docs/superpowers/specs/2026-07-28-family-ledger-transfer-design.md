# 资产记账：零余额保留与条目间转移

**日期**：2026-07-28  
**状态**：已确认（方案 A）  
**路由**：`/view/family/ledger`

## 目标

1. 资产条目金额可为 `0`，仍出现在资产 Table；转移/改金额后**不自动删除**源条目。
2. 编辑资产条目时可选用「转移」：将部分或全部金额转到另一条已有资产。

## 非目标

- 不新建转移流水表 / 不做 DDL（本仓只读写已有 `family_ledger_items`）。
- 负债条目、新建条目不提供转移。
- 不支持跨用户、跨 side（资产 ↔ 负债）转移。

## 零余额

- DB 已允许 `amount >= 0`。
- UI：资产 Table 不过滤 `amount === 0`；整笔转出后源条目保留为 `¥0.00`。
- 删除仅由用户显式点「删除」。

## 转移交互（方案 A）

仅在 **编辑** 且类型为 **资产** 时展示：

| 表单项   | 行为                                                                     |
| -------- | ------------------------------------------------------------------------ |
| 转移至   | 可选；选项为其他资产条目（含金额 0），排除自身；文案含名称 / 成员 / 金额 |
| 转移金额 | 选择目标后必填；`0.01`～源条目当前余额（编辑打开时的余额）               |
| 金额     | 开启转移时改为只读，展示「转移后余额」= 当前余额 − 转移金额              |

未选转移目标时，金额字段仍可直接改绝对余额（现有行为）。

同一次保存仍可改名称、分类、成员、四笔钱、备注。

## 计算与校验（纯函数）

输入：`sourceAmount`、`transferAmount`、`targetAmount`；另需业务校验 `fromId !== toId`、两侧均为资产。

```
transferAmount ∈ (0, sourceAmount]
sourceAfter = roundMoney(sourceAmount − transferAmount)  // 可为 0
targetAfter = roundMoney(targetAmount + transferAmount)
```

非法：金额 ≤ 0、超过源余额、自转、目标非资产 → 抛错，Modal 不关闭。

## 持久化

`FamilyFinanceRepository.transferLedgerAmount({ fromId, toId, amount })`：

1. 读取并校验两条均为当前用户资产且 `fromId !== toId`。
2. 用纯函数算新余额。
3. 更新源时带 `amount = 原余额` 前置条件（乐观锁）；不匹配则报「余额已变更」。
4. 再更新目标（同样带原余额前置条件）；若失败则**把源金额回滚**到转移前，并提示勿在未核对时盲目重试同额。
5. 页面：转移成功后立刻清空 `transferToId` / `transferAmount`，同步本地 `editing.amount` 与列表中的源/目标行；若后续 upsert 失败也会 `reload()`，避免关闭弹窗后仍显示转移前余额。
6. 再 `upsertLedgerItem` 写源条目非金额字段（金额以转移结果为准）。

源余额为 `0` 时不展示转移表单项。

## 测试

- 纯函数：部分转移、整笔转空（源为 0）、超额、零/负金额。
- UI 行为由页面集成；单测覆盖纯函数为主。
