# 指数仪表盘 Bugfix 设计

## 目标与范围

修复指数仪表盘评审中发现的功能正确性、加载性能和测试稳定性问题。Next.js、React、React DOM 及其类型依赖版本保持不变，本次不处理框架安全升级。

## 设计

### 详情请求一致性

指数选择或 K 线窗口变化时，每次详情加载获得单调递增的请求编号。只有当前最新编号对应的请求可以写入估值、行业权重、K 线、错误和加载状态；较早请求即使更晚返回，也必须被忽略。组件卸载后同样不得更新状态。

### 估值比较语义

估值与历史均值的比较结果使用 `below`、`equal`、`above` 和 `null` 四种状态，避免把“等于”编码成布尔值 `false` 后误显示为“高于/偏贵”。摘要、标签和测试共享该语义。

### 图表按需加载

行业权重与 ETF K 线面板通过 `next/dynamic` 拆分为独立客户端 chunk，并提供与现有卡片一致的加载占位。指数选择与数据请求逻辑仍留在主客户端组件中。

### E2E 数据隔离

“无估值”场景在 Playwright 中拦截 Supabase `etf_valuation` 请求并返回固定空结果，不再依赖某个真实指数长期缺少数据。首页与真实共享行情的主链路测试保持不变。

## 验证

- 单元测试覆盖估值低于、等于、高于和缺失四种状态。
- 回归测试验证旧请求结果不会覆盖新请求。
- 运行全部 Jest 测试、生产构建和指数仪表盘 Playwright E2E。
- 对比生产构建输出，确认指数仪表盘首屏 JS 小于修复前的 784 kB。
